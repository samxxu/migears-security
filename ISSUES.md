## Verdict / 结论

The cryptography underneath is still sound (`random_bytes`, `hash_equals`, Encrypt-then-MAC all correct), but **all four steps of the session lifecycle are missing**: no rotation, no revocation, no `Secure` flag, no token rotation.

密码学底层依然扎实（`random_bytes`、`hash_equals`、Encrypt-then-MAC 全部正确），但**会话生命周期的四个环节都没有做**：不轮换、不可吊销、Cookie 无 Secure、令牌不轮换。

## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/MiAuth.php:102-109`
- **Verification / 验证**: reproduced (repo-wide grep)
- **EN**: Session fixation: `login()` only writes `$_SESSION` and never calls `session_regenerate_id()` — zero call sites in the whole module. An attacker who plants a known `PHPSESSID` gets an authenticated session the moment the victim logs in
- **中文**: 会话固定：`login()` 只写 `$_SESSION` 而不调用 `session_regenerate_id()`，全模块源码零调用。攻击者预置已知 `PHPSESSID` 后，受害者登录即让该 ID 进入已认证态

### P0-2

- **Status / 状态**: Open
- **Where / 位置**: `src/MiAuth.php:114,147-182,185-193`
- **Verification / 验证**: reproduced
- **EN**: The remember-me cookie is a self-contained ciphertext with no server-side record: `logout()` only deletes the client cookie, so a copied old cookie stays valid and replayable for the default 30 days, and changing the password does not invalidate it
- **中文**: remember-me Cookie 是自包含密文，服务端无任何记录：`logout()` 只删客户端 Cookie，被拷走的旧 Cookie 在默认 30 天内始终有效且可无限重放，改密也无法失效
