  - **The fork — `classic()`'s remember-me Cookie flags have no seam.** Its private `cookieSet` /
    `cookieRemove` closures call `setcookie()` directly (`src/MiAuth.php:160-177`) and discard its
    return, and the CLI SAPI does not expose the resulting header (`headers_list()` is empty), so the
    remember-me Cookie's own Secure / HttpOnly / SameSite flags — and the write half of the remember-me
    superglobal path — cannot be asserted from `./vendor/bin/phpunit`. Closing that gap means changing a
    public API or accepting the boundary, and the pick is yours:
    - **Option A — no seam.** Leave the flags on the documented-but-unobserved list; the closure is
      asserted only by reading `src/MiAuth.php:160-177`. Cost: zero churn, and the most security-relevant
      flags of the wrapper stay without a regression guard.
    - **Option B — inject a session/cookie transport into `classic()`** (an optional callable set in
      `$options`, or one new optional parameter, defaulting to the present `setcookie()`/`$_COOKIE`
      closures). Cost: a public-API change on a security-sensitive factory; the flags become assertable
      and the default behaviour is unchanged.
    - **Option C — assert the flags outside the unit suite** (a `php -S`-style harness or a separate
      integration job). Cost: heavier CI, no unit coverage, and the check stops being part of a plain
      `./vendor/bin/phpunit`.
    Until one is chosen, this half is left alone and the three tests above stand.
